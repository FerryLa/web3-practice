# 사용자 데이터베이스

## Xsolla 저장소

- 사용자 저장소로 기본 제공되는 **Xsolla 저장소**가 정상 연결돼 있는지 확인했다.
- Google 로그인 후 만들어진 사용자 계정은 Xsolla가 관리한다.
- 현재 학습에서는 별도의 MySQL, PostgreSQL 또는 자체 인증 서버를 연결하지 않는다.

## 사용자의 의미

사용자 목록에서는 일반적으로 다음 정보를 확인하고 관리한다.

- Xsolla Login 사용자 ID
- 이메일과 기본 프로필
- 계정 생성 시각과 최근 활동
- 연결된 소셜 네트워크
- 차단 상태와 사용자 특성

Google 테스트 로그인 사용자가 목록에 나타나면 다음 연결이 정상 동작한 것이다.

```text
Google 인증 → Xsolla 사용자 확인 또는 생성 → Xsolla 저장소 기록 → JWT 발급
```

## 추가 사용자 정보

- 가입 시 별도의 사용자 필드를 추가로 수집하는 기능이다.
- 현재는 사용하지 않는다.
- 닉네임이나 게임 사용자 ID가 반드시 필요해질 때 목적을 정한 후 추가한다.

## 사용자 특성 스키마

사용자 특성은 이후 개인화 카탈로그에서 활용할 수 있다. 예시는 다음과 같다.

| 특성 | 예시 값 | 활용 예시 |
|---|---|---|
| `vip_tier` | `gold` | VIP 전용 BLUC 패키지 표시 |
| `first_purchase` | `true` | 첫 구매 보너스 표시 |
| `bonus_eligible` | `true` | 추가 BLUC 혜택 표시 |
| `region` | `KR` | 지역별 상품 또는 가격 정책 적용 |

현재는 스키마를 만들지 않고, BLUC 기본 카탈로그를 만든 뒤 개인화 단계에서 설계한다.

## 자체 데이터베이스가 필요한 시점

- 기존 게임 계정 DB와 로그인 계정을 연결해야 할 때
- 구매 결과를 게임 인벤토리에 지급해야 할 때
- 사내 회원 정책과 제재 시스템을 직접 운영해야 할 때
- Xsolla 외부에서도 동일한 사용자 속성을 관리해야 할 때

이 경우에도 브라우저가 DB에 직접 접근하지 않고 백엔드가 Xsolla 토큰을 검증한 뒤 안전하게 처리한다.
