# 02. BLUC 상품 카탈로그

이번 장에서는 Xsolla Item Catalog에 가상 화폐 `BLUC`를 만들고, 실제 화폐로 구매할 수 있는 패키지형 상품을 구성했다. 상품 이미지는 BLUC 1단위 대표 이미지 1개와 패키지 카드 이미지 6개로 구성했다.

## 한 문장 복습

- **가상 화폐 생성**: 패키지를 구매했을 때 사용자에게 지급할 기본 화폐 `BLUC`를 정의하는 작업
- **가상 화폐 패키지 생성**: 정해진 수량의 BLUC와 실제 판매 가격을 하나의 상품으로 묶는 작업
- **SKU 설정**: 카탈로그 조회, 주문, 로그에서 상품을 식별할 고유한 바코드를 지정하는 작업
- **상품 이미지 적용**: 패키지 단계가 한눈에 구분되도록 카드용 시각 자료를 연결하는 작업
- **카탈로그 API 조회**: Publisher Account에 등록한 상품을 웹숍 프런트엔드가 JSON으로 가져오는 작업
- **JWT 포함 조회**: 로그인 사용자의 구매 제한, 프로모션과 개인화 결과를 포함해 카탈로그를 가져오는 작업

## 상품 구조

Xsolla에서는 BLUC와 BLUC 패키지를 별개의 아이템으로 관리한다.

```text
가상 화폐: BLUC
  ├─ 1,000 BLUC 패키지
  ├─ 2,050 BLUC 패키지
  ├─ 4,150 BLUC 패키지
  ├─ 10,700 BLUC 패키지
  ├─ 23,500 BLUC 패키지
  └─ 53,000 BLUC 패키지
```

패키지의 `content.quantity`에는 기본 수량과 보너스를 합친 총 BLUC 수량을 입력한다. 기본 수량과 보너스의 구분은 상품명, 설명 또는 프런트엔드 표시 정보로 제공한다.

## 패키지 구성

| SKU | 상품명 | 기본 BLUC | 보너스 BLUC | 지급 총수량 | 가격 |
|---|---|---:|---:|---:|---:|
| `bluc_pack_1000` | 1,000 BLUC | 850 | 150 | 1,000 | $4.99 |
| `bluc_pack_2050` | 2,050 BLUC | 1,700 | 350 | 2,050 | $9.99 |
| `bluc_pack_4150` | 4,150 BLUC | 3,400 | 750 | 4,150 | $19.99 |
| `bluc_pack_10700` | 10,700 BLUC | 8,500 | 2,200 | 10,700 | $49.99 |
| `bluc_pack_23500` | 23,500 BLUC | 17,000 | 6,500 | 23,500 | $99.99 |
| `bluc_pack_53000` | 53,000 BLUC | 34,000 | 19,000 | 53,000 | $199.99 |

> 실제 Publisher Account에 입력한 SKU가 이 표와 다르면 API와 프런트엔드에서는 Publisher Account에 저장된 값을 기준으로 사용한다.

## SKU가 바코드인 이유

상품명은 사용자에게 보여주는 문구라서 번역하거나 수정할 수 있지만 SKU는 시스템이 상품을 구별하는 고유 식별자다.

```text
SKU
  → 카탈로그에서 상품 조회
  → 상품 카드와 가격 연결
  → 주문할 상품 지정
  → 결제 및 지급 로그 추적
```

따라서 SKU는 생성 후 가급적 변경하지 않고, 상품 수량이나 표시 이름이 바뀌어도 동일한 상품의 식별자로 유지한다.

## 상품 이미지

이미지 안에는 수량, 가격 또는 보너스 문구를 넣지 않았다. 수치 정보는 프런트엔드 텍스트로 표시하여 통화 변경, 번역과 가격 수정에 대응한다.

## 카탈로그 API

개발용 기본 조회 주소:

```text
https://store.xsolla.com/api/v2/project/312439/items/virtual_currency/package?limit=50&offset=0&locale=ko&country=KR
```

URL의 `930170`은 Publisher Account ID이고, 카탈로그 API에는 **프로젝트 ID `312439`**를 사용한다.

응답에서 확인할 핵심 필드는 다음과 같다.

- `items[].sku`: 상품 바코드
- `items[].name`: 카드에 표시할 상품명
- `items[].price`: 금액과 실제 통화
- `items[].content`: 지급할 가상 화폐와 총수량
- `items[].image_url`: Publisher Account에 업로드한 상품 이미지
- `items[].groups`: 상품 분류
- `items[].attributes`: 필터와 개인화에 사용할 속성

인증 없이 요청하면 기본 카탈로그를 받을 수 있다. 로그인 이후 `Authorization: Bearer <사용자 JWT>` 헤더를 포함하면 사용자별 구매 제한, 프로모션과 개인화 결과가 반영될 수 있다.

2026-08-07에 공개 카탈로그 API를 조회해 다음 항목을 확인했다.

| SKU | 가격 | 지급 수량 | 판매 가능 | 이미지 |
|---|---:|---:|---|---|
| `bluc_pack_1000` | $4.99 | 1,000 | `true` | 있음 |
| `bluc_pack_2050` | $9.99 | 2,050 | `true` | 있음 |
| `bluc_pack_4150` | $19.99 | 4,150 | `true` | 있음 |
| `bluc_pack_10700` | $49.99 | 10,700 | `true` | 있음 |
| `bluc_pack_23500` | $99.99 | 23,500 | `true` | 있음 |

응답은 `items` 6개와 `has_more: false`를 반환했다. 이 검증은 Publisher Account의 설정이 Xsolla 서버에 저장·공개되어 실제 웹숍 프런트엔드가 사용할 JSON으로 전달되는지 확인하는 과정이다. 결제창, 실제 결제, 웹훅과 게임 내 BLUC 지급은 이후 주문·지급 통합 단계에서 별도로 테스트한다.
